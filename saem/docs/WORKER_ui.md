SCREENS (tabs).
1 Papers: bring papers in by pasting text or uploading .txt, .csv or .docx (DOCX is zip plus XML, read with zipfile; PDF and scans are not supported yet: say so and tell the user to export text or CSV). 2 Forecast: stat cards (years covered, source size, back-test hit rate vs random), verdict banner (forecast.verdict), expected weightage by chapter (bars and trend arrows), the predicted questions grouped by topic with rank badge, probability meter, reason chip, example question and year, "Shuffle examples", Export CSV, receipt id.
3 Paper: assemble (paper.assemble) with n and seed; preview with each question's chance, source label (Math Brain or Paper) and answer and solution in <details>; Download CSV (paper.rows); print view; Start test.
4 Test: the mock-test machine exactly as in the mock-test page: test bar with title and timer, section tabs, question panel, options, palette with the five states (not visited, not answered, answered, marked, answered and marked), Clear response, Mark for review and next, Save and next, Previous, Submit with a confirm step showing answered, unanswered and marked. Each action is a link or a <form> POST; the run state (answers, marks, visited, seconds per question, deadline) lives on the server. Timer: CSS-only countdown (an animated @property integer shown through counter()) plus <meta http-equiv="refresh" content="N;url=..."> that auto-submits at the deadline; the server rejects answers after the deadline. Also an untimed practice mode and topic drills (paper.drill).
5 Results: marks, percent, correct, incorrect, unattempted, section and topic breakdown (test.grade), time per question bars, change against the last attempt on the same paper (mcq.hash), full review with the right option, the student's pick, explanation and source label. It updates mastery (study.learn) and saves the attempt (test.record, with study.forget keeping memory bounded).
6 Study: where the next hour pays most (study.plan) with a Practice button per topic.
7 Rules: the six constitution rules with live audit status (core.audit), the self-test (core.selfTest), core id and version (core.info), and a plain statement of what the product will not claim.
Footer on every page: "Revision priorities from patterns in past papers, not a leaked paper and not a guarantee." Language switch English / हिन्दी on every page (saem/i18n.py: interface strings only; question text stays as given). Storage: JSON files under the data dir, atomic writes, nothing leaves the machine. Single-user local mode first; keep run state keyed by a random cookie so two students on one server do not clash.
